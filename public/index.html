Start here New to this page? Follow these 6 steps in order What is this? A lock service that runs on 5 machines. A lock lets only ONE program at a time use something shared, and the 5 machines keep working together even when some of them fail.
  1. 1
    Look at the cluster

    The 5 circles are the 5 machines. The gold one is the leader: it handles every request. The blue ones are followers that keep copies.

    Why it matters: 5 copies means no single machine can take the service down.
  2. 2
    Take a lock

    A program asks for the lock called orders-db. It is granted for 8 seconds and given a number called a token.

    Why it matters: the service promises ONE holder at a time (mutual exclusion).
  3. 3
    Ask again as someone else

    While client-A holds it, client-B asks for the same lock and is refused. Only one holder at a time.

    Why it matters: this refusal is the proof that two programs can never hold the same lock.
  4. 4
    Crash the leader

    Watch the ring: the 4 other machines elect a new leader in about a second, and your lock is still there.

    Why it matters: fault tolerance. The lock was saved on at least 3 machines, so a new leader still knows about it.
  5. 5
    Cut the network

    Disconnect the leader from the rest. Only the group with 3 or more machines can keep working. Then reconnect.

    Why it matters: the majority rule. Only the side with 3+ machines can act, so there are never two leaders (no split brain).
  6. 6
    Protect the data

    A slow program can wake up and write with an expired lock. A fencing token lets the storage refuse it. See it happen.

    Why it matters: a lease alone is not enough. Tokens make a late, stale write harmless.

Words you will see

Machine / node
One of the 5 servers. Each keeps a full copy of the lock table.
Leader / follower
The leader takes every request. Followers copy it and wait to take over.
Term
The election round number. It goes up each time a new leader is chosen.
Majority (quorum)
3 of 5. A decision only counts if 3 machines agree, so two groups can never both decide.
Resource name
Just a label for the thing being locked (a database, a file). Any text works. A different name gives a separate lock, so two names never block each other.
Lock and lease
A lock lets one program use something. A lease is a lock with a timer, so it frees itself.
Client name
Who is asking. Pretend to be two programs by using client-A and client-B for the same resource.
Fencing token
A number that only goes up with each new lock. Storage refuses writes with an old number.
Log / commit
The list of decisions each machine stores. Committed means a majority has saved it.
